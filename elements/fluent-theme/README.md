# fluent-theme

A HAXcms theme in the layout of the Fluent 2 documentation site, [fluent2.microsoft.design](https://fluent2.microsoft.design), built on the **Fluent 2 DDD bridge**:

- **Header**: a light 56px bar on `colorNeutralBackground1` with subtle icon buttons for the menu, search and dark mode.
- **Navigation drawer**: on `colorNeutralBackground2`, with the current item on the subtle selected background and Fluent's 4px brand pill. Below 1024px it overlays the page.
- **Content**: pages sit on a rounded `colorNeutralBackground1` card with Fluent's `shadow4`, opening with the breadcrumb, a semibold title and the page description as lead text. Previous and next close the page.

## What the bridge does

HAX blocks only read DDD tokens (`--ddd-*`). This package re-expresses Fluent's tokens under the CSS names Fluent itself uses (`--colorNeutralForeground1`, `--borderRadiusMedium`, ...; the global palettes and the web brand ramp as `--fluent-*`) and points every DDD token a block reads at the closest Fluent token. While this theme is active, blocks take on Fluent color, Segoe UI type, Fluent's corner radii and shadows, its focus stroke, motion curves and control heights. Authored content stays plain DDD content that renders in any other theme.

The design system registers as `fluent` with `extends: "ddd"` in `DesignSystemManager`, so DDD's styles, data attributes and HAX authoring options stay in place. A site can also keep its own theme and choose Fluent 2 as its design system.

| File | What it is |
|---|---|
| `design-system/bridge.json` | The authored mapping: the `@fluentui/tokens` source (read with the `js-literals` format), icons, and each DDD token → Fluent token |
| `lib/FluentTokens.js` | Generated: the Fluent tokens the map and theme use, as `light-dark()` pairs |
| `lib/FluentDDDMap.js` | Generated: the `--ddd-*` → Fluent remap |
| `lib/FluentIcons.js`, `icons/` | Generated: HAX icon names drawn in Fluent UI System Icons |
| `lib/fluent.ddd-map.json` | Generated: the full map with resolved values, coverage per contract tier and a contrast report |
| `lib/FluentDesignSystem.js` | Registers and activates the `fluent` design system |
| `fluent-theme.js` | The theme |

## Coverage

Checked against the shared [bridge contract](../d-d-d/design-system/bridge/README.md): identity 96%, feel 57%, semantic 42% (density at Fluent's spacing steps: 12px surface padding and stack gap, 8px inline gap), component 75%, structure locked. Kept as DDD on purpose: light and black font weights (Fluent has regular, medium, semibold and bold), state opacities (Fluent uses hover and pressed colors), border widths, and heading/body sizes (Fluent body is 14px, under the 16px floor).

Fluent publishes its tokens only as JavaScript. The bridge reads `@fluentui/tokens` (the package Fluent UI React 9 builds its themes from) for literal values and palette references; nothing is evaluated. Its shared status and persona palettes are computed in code, so named colors map to the global shared colors directly.

## Rebuilding the tokens

```
yarn ddd:bridge elements/fluent-theme          # from the monorepo root
yarn ddd:bridge elements/fluent-theme --check  # fail if the generated files are stale
```
