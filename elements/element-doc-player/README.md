# element-doc-player

Living documentation for a web component in one tag: an animated walkthrough, the live demo, generated documentation and the HAX schema, with copy buttons for HTML, the JS import, `npm i` and the CDN script.

```html
<element-doc-player
  docs-src="./meme-maker.docs.json"
  motion-src="../lib/meme-maker.motion.json"
></element-doc-player>
```

| Attribute | Purpose |
| --- | --- |
| `docs-src` | Docs data file generated by `scripts/extract-element-docs.mjs` |
| `motion-src` | Optional storyboard. Without it the Walkthrough tab is left out |
| `tab` | `motion`, `demo`, `docs` or `schema` |
| `autoplay` | Start the walkthrough when it loads. Reduced motion shows a still frame |
| `demo-href`, `docs-href` | Links for the Open demo and Open documentation buttons |

## Where the data comes from

- Docs data is generated from the element source: `node scripts/extract-element-docs.mjs <out-dir> [element ...]`.
- A storyboard is a JSON file kept beside the element at `lib/<tag>.motion.json`. It records a surface hash of the element it was written for.
- When attributes, HAX settings, slots, events or demo schema change, the hash changes and the player shows the walkthrough as stale. `node scripts/extract-element-docs.mjs --status` lists every storyboard as `reviewed`, `awaiting` or `stale`.
- A storyboard counts as reviewed only when its `review` block is `{ "status": "approved", "hash": "<current hash>" }`.

## Theming

Colors come from DDD tokens through `--edp-main`, `--edp-ground`, `--edp-second`, `--edp-accent`, `--edp-line` and `--edp-panel`. Override them on the element to restyle it.
